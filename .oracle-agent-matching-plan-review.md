## Explicit user rejection of your previous auto-write tightening
In the previous review you recommended: auto-write only when there is a Douban↔IMDb identity chain; items without an IMDb anchor go to human review.

The user rejected this. Their reason: Douban’s IMDb is not fully trustworthy; if a usable IMDb exists, deterministic matching usually already finds TMDB, so those items never reach the agent. Therefore auto-write should be decided by **confidence + verifier**, not by requiring a Douban IMDb chain.

The locked compromise already in the spec:
- No Douban IMDb identity-chain hard requirement for auto-write.
- If Douban has an IMDb AND the candidate also has an IMDb, they must be identical; conflict **downgrades to suggest**, not auto-write.
- Missing year does **not** by itself veto auto-write; obvious remake year conflict does.

Do not re-impose the IMDb-chain gate unless you can show a concrete residual poisoning path that confidence+verifier cannot catch, with an example from this codebase.
